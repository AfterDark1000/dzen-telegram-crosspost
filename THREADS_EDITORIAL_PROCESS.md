# ХПИИ: авторские посты для Threads

Этот механизм уже подключён к рабочему кросспостингу. Никакой сайт для редактирования, сторонний сервис, платный API или дополнительный бот не требуется.

## Как пользователь работает с редактором ChatGPT

1. Редактор выдаёт статью Дзена **с окончательным заголовком** и самостоятельный авторский Threads-пост.
2. Пользователь при необходимости редактирует текст в чате.
3. Команда **«Ок, тредс берём»** означает: сохраните **последнюю утверждённую версию** текста Threads и соответствующий заголовок статьи Дзена в GitHub.
4. ChatGPT сначала читает текущий `threads_editorial_queue.json`, проверяет существующие записи, затем через подключённый GitHub **создаёт или обновляет запись**. Не выдумывать успех; подтвердить только после успешного сохранения в GitHub.
5. В Дзене пользователь публикует или планирует статью как обычно. При выходе статьи существующий GitHub Actions сопоставляет заголовки и публикует **ровно утверждённый** Threads-текст. **Только при явной пометке** добавляет в конце настоящую ссылку на вышедшую статью.

Команда «Исправь тредс: …» после утверждения означает обновление **той же записи**, если `status=approved`. Если `status=published`, **ничего не перепубликовывать**; объяснить, что пост уже ушёл.

## Машинный формат

Файл: [threads_editorial_queue.json](threads_editorial_queue.json)

```json
{
  "schema_version": 1,
  "items": [
    {
      "id": "story-20261020-example",
      "dzen_title": "Точный заголовок статьи для Дзена",
      "threads_text": "Последняя одобренная авторская версия поста.",
      "include_dzen_link": false,
      "status": "approved"
    }
  ]
}
```

- `id`: уникальный читаемый технический номер, только латиница, цифры, `_`, `-`, от 8 до 72 символов. Повторная правка **не создаёт новый ID**.
- `dzen_title`: заголовок именно из подготовленной статьи Дзена. Проверяется строго, с игнорированием регистра, пробелов, пунктуации и ё/е. **Не угадывать** переименованные новости по смыслу.
- `threads_text`: утверждённый русскоязычный текст до **480 символов**. Программа его не переписывает и не сокращает.
- `include_dzen_link`: `true` только для действительно содержательных, расширенных статей, где читатель найдёт дополнительные подробности; иначе `false`. По умолчанию `false`. Не делать ссылки обязательными или циклически через каждые три поста. При `true` конвейер после выхода материала берёт его **настоящий адрес** и приписывает `Подробнее в Дзене: https://dzen.ru/a/...`. Авторский текст при этом сохраняется дословно. Общая длина должна укладываться в 500 символов. При превышении лимита/подозрительной ссылке пост **не публикуется**, редактор должен исправить текст и заново утвердить.
- `status`: `approved`, `on_hold`, `published`. Новая одобренная запись = `approved`. При `published` программа сама сохраняет `dzen_id`, `dzen_url`, `threads_post_id`.

Нельзя допускать две строки с одинаковым нормализованным заголовком; нельзя автоматически преобразовывать другие статьи Дзена в Threads-посты.

## Принцип защиты от дублей

- История `seen_threads_articles.json` сохраняется: ранее опубликованные статьи повторно не отправляются.
- Если очереди нет или она пуста, **новых публикаций Threads не будет**.
- Если заголовок Дзена не совпадает, нет однозначного соответствия или очередь повреждена, публикация не выполняется.
- Перед отправкой запрашиваются последние 100 публикаций Threads; при сбое проверки система не отправляет ничего.
- Если Threads уже содержит точный текст публикации (для помеченного материала — включая ссылку на Дзен), программа фиксирует отправку без повтора.
- После успешной отправки GitHub Actions сохраняет очередь со статусом `published` и список отправленных ID **одним коммитом**.

Этот механизм снижает риск дублей, но не является математической гарантией при любых сетевых сбоях. При неясном статусе публикации нужно проверять Threads.

**Приватность:** этот репозиторий может быть публичным. Не размещайте в очереди секреты или конфиденциальные материалы; будущий текст публикации может быть виден в GitHub до выхода в Дзене.
